## 已保留的翻译能力

0.3.1优化已有功能：同段内移动鼠标不会重新计算悬停等待；切换输入框与新选区立即作废旧请求；缓存结果整批写入、访问时间合并写回，清空与迟到读写互相隔离，缓存异常直接提示。[改进依据与验证](docs/existing-feature-refinement.md)。

Chrome Manifest V3 网页、文件与字幕翻译扩展。使用自己的 Google Cloud Translation、OpenAI、DeepSeek 或 Claude API，默认简体中文双语显示。支持滚动翻译、动态正文、停止、恢复、手动重试与可选缓存。

这是依据页面处理原理独立编写的客户端，不包含沉浸式翻译的源码、品牌、规则、密钥或付费后端。

## 加载与配置

1. 解压正式 ZIP。打开 Chrome 的 `chrome://extensions`，开启开发者模式，选择“加载已解压的扩展程序”，选择包含 manifest.json 的目录。
2. 打开扩展设置，选择服务，填写自己的 API Key。OpenAI/DeepSeek/Claude 还需填写该账户已开通、支持对应接口的模型名称。Google 使用 Cloud Translation Basic v2。
3. 保存连接时授予所选服务域名访问权限。保存不调用 API；“测试连接”会发送固定英文短句，可能产生费用。
4. 打开普通网页，从浏览器工具栏打开扩展，点击“翻译此页”。“停止”保留已完成译文，“恢复原文”停止并移除译文。
5. 如需打开外语网页后自动翻译，在设置页或弹窗开启对应开关，并一次性授予普通网页访问权限。开启后已打开的页面刷新一次；可随时关闭。目标语言/语言不确定的页面跳过，后台标签页等激活后再开始。自动模式也使用你的API并可能计费。
6. 划词、悬停和输入框翻译可在设置或弹窗分别开启。划词后点击按钮；按住Alt悬停450ms；输入框点击按钮或Alt+T，先预览再确认替换，可撤销。输入目标语言单独设置，初始English。首次需授权普通网页，现有可访问页面立即生效。见[随手翻译说明](docs/quick-translation.md)。

0.2.2把首屏短段合批，并让完整缓存先显示。同一120ms本机受控接口测试中，6段首屏由864ms降到183ms、6次请求降为1次；内存命中6ms且无请求。冷启动首条译文没有证实变快，仍受API响应影响。[具体测量与限制](docs/speed-and-auto.md)。

0.2.3增加“一键双语字幕（现成字幕）”：先读主视频的现成外语字幕，再调用文字翻译，逐批显示；不会自动转去音频识别。已知人工轨优先，纯目标语言/未知语言不自动选择。无字幕、空体或需登录时明确提示。[实现与公开页验证](docs/existing-caption-fast-path.md)。

密钥保存在本地扩展存储，不是系统级保险箱。网页聊天登录、ChatGPT/Claude 订阅不代替 API Key。没有附带密钥、自动模型猜测或代理服务。DeepSeek翻译显式关闭思考模式，单次最多4096输出tokens。Claude 此版本固定 Messages API 的 `2026-10-21` 版本与 Bearer 鉴权；账户不支持时明确失败，不自动改用旧版本。

## 请求量与失败处理

- 用户主动启动或开启自动翻译后，当前顶层正文进入可见区域附近时才发送。排除编辑框、导航、隐藏文本、按钮、代码等。
- 每轮上限 300 个片段、60,000 Unicode 字符；每片最多 1200、每批最多 8 片/2400 字符。达到上限暂停，点击继续会新增一轮额度，可能增加费用。
- 四服务共用最多 2 个在途请求。没有自动网络重试，没有自动切换供应商。请求超时为 25 秒；停止会中止本地 fetch，不能保证远端未处理或不计费。
- 格式错误、拒答、缺少/重复条目不会当成译文；失败段落保留原文和错误标记。限流/网络问题需要手动重试，鉴权或配置问题需要修复后重新开始。
- 后台中断后显示结果未知，必须显式重新开始，可能重复计费。不会自动重放旧请求。
- 可选持久缓存保存在扩展源 IndexedDB，30 天有效、最多 1000 项；默认关闭。扩展运行期间仍做有界内存去重。清空缓存不清除密钥。

## 文件与字幕工作台

从普通网页的扩展弹窗打开“文件与字幕工作台”。文档和字幕在本机读取，只有待译文字发给文本服务，导出另存原件。

| 格式/功能          | 0.3.1 行为                                                                                                                     |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| PDF                | 本地文字提取，扫描页英文/简中 OCR；原页与译文对照。双语 PDF 保留原页外观并随页附译文页，移除原页交互批注/动作；也可导出 HTML。 |
| EPUB               | 按书籍 spine 顺序翻译，保留资源并导出双语 EPUB；拒绝加密/DRM。                                                                 |
| TXT/Markdown/HTML  | 双语阅读与导出；HTML 不执行原件脚本、不加载远程资源。                                                                          |
| DOCX               | 正文、页眉页脚、脚注尾注文字；追加译文后导出 DOCX。                                                                            |
| PPTX               | 按实际幻灯片顺序处理正文与备注，追加译文段落，导出 PPTX。                                                                      |
| XLSX               | 共享字符串/inlineStr 单元格追加译文，保留公式、数字与样式。                                                                    |
| 已有视频字幕       | 原生轨道、YouTube/B站可用CC或导入SRT/VTT；双语字幕随播放和跳转同步，两站挂载播放器内，支持容器全屏、恢复和导出。               |
| 字幕工作台         | SRT/VTT 导入、配对本地音视频预览、手动播放偏移、翻译与导出、应用到来源页；应用已有结果不再次请求。                             |
| 上传 AI 字幕       | 小于25 MiB的音视频文件 → 独立语音识别接口 → 真实分段时间戳 → 文本翻译 → SRT/VTT；无时间戳明确失败。                            |
| 当前标签页 AI 字幕 | 从视频页点击扩展进入工作台，保持1倍速播放再点击录音；每15秒独立编码并识别，按实测视频时钟追加字幕，单次最多120段。             |

AI 字幕需另外配置语音接口、模型、响应协议和 Key，并授予对应域名权限。保存设置不调用接口。支持返回带时间戳的 `verbose_json`、`diarized_json`、SRT、VTT 的兼容接口，具体模型能力由服务决定；不拿文本接口冒充语音识别。当前官方协议与变化记录见验证文档。

标签页录音捕获整个标签页声音，识别延迟通常为片段时长加服务耗时。停止录音会完成已录片段；暂停、跳转、变速、换源或离开原页会停止并丢弃最后不完整片段。关闭工作台会终止音轨、关闭 AudioContext、取消识别并删除本次音频与识别记录。可主动清除本次记录；重新开始/重试可能再次计费。录音不自动重启、不访问麦克风。

## 能力边界

普通网页只追加纯文本译文，保留原文链接与交互。Office 追加译文可能改变换行、分页或溢出文本框；未保证原版式一模一样。扫描识别可能有错字，尤其复杂版面、手写、低分辨率或繁体字。PDF密码/加密或解析失败会明确报错。

视频支持顶层可访问 video/textTracks、手动字幕及 YouTube/B站字幕适配。当前播放位置附近优先翻译，跳转后调整待处理队列；切换视频/分P会停止旧字幕和录音。B站公开页的导入字幕显示、跳转、全屏和同网址换P已实测；其原生CC要求登录，正向读取尚未验证。YouTube本轮遇到机器人确认，未完成线上播放验收；此前读到49轨，但字幕请求为空。限制不会自动切换为付费AI识别。详见[两站验证与调用链](docs/platform-subtitles.md)。跨域iframe、DRM、持续滚动的直播字幕和自动追踪新增cue尚未支持。AI录音字幕是分段识别，不是即时逐字转录。

仍无仅译文模式、术语表、跨域 iframe、封闭Shadow DOM、自动站点规则、云同步或遥测。输入支持普通控件和简单富文本，专用编辑器不作通用兼容保证。Chrome 内部页与受限页面无法注入。

目标为 Chrome 120+，实际隔离浏览器验证版本为 Chrome for Testing 151.0.7922.34。DeepSeek已用两次真实请求验证合成短文与字幕，测量见[真实测试记录](docs/deepseek-live.md)。其它三种文本服务及语音识别仍是模拟接口验证；结果不代表任意账户、模型或网络都可用。

## 开发验证

需要 Node 24（测试器参数 `--test-isolation=none`）。先安装开发依赖，再运行测试：

```powershell
npm ci
node --test --test-isolation=none test/*.test.mjs
```

浏览器验证需要 Playwright 和它的 Chromium。设置 `BT_PLAYWRIGHT` 为 Playwright 包路径（非标准安装时），`PLAYWRIGHT_BROWSERS_PATH` 为浏览器目录，`BT_OUTPUT` 为测试产物目录，然后按顺序运行 `node test/browser.mjs`、`node test/browser-documents.mjs`、`node test/browser-video.mjs`、`node test/browser-asr.mjs`、`node test/browser-capture.mjs`。这些测试共用8787端口，不要并发运行。`node test/browser-document-safety.mjs`检查中文OCR、初始化取消、PDF动作与媒体页面关闭清理。浏览器测试创建自己的临时 profile 和复制测试包，把四服务改接 `127.0.0.1:8787`，只使用 `test-key`，不会接触日常 Chrome。

测试把 popup HTML 作为标签页打开，因此仅在复制的测试包中将目标页固定为本机夹具；录音测试另外通过浏览器协议在真实 tab target 上触发扩展操作并实际捕获标签页音频，但仍未人工验收日常浏览器的弹窗外观。正式包不带测试域名权限或此绑定。测试结束关闭自己创建的浏览器和模拟服务，profile 及证据保留在 BT_OUTPUT。

完整验证范围见 [验证记录](docs/verification.md)，实现与调用链见 [实现说明](docs/implementation.md)，错误与回退见 [专项审计](docs/fallback-audit.md)，发送数据见 [数据流说明](docs/data-flow.md)。打包可执行 `powershell -ExecutionPolicy Bypass -File scripts/package.ps1`（仅本次进程执行脚本，不更改系统策略）。正式包包含 manifest.json、src 与项目 LICENSE。
