## 使用

视频页打开扩展，点击“一键双语字幕（现成字幕）”。扩展优先读取主视频可访问的现成外语轨道，否则查询当前YouTube/B站字幕元数据；确认拿到有效时间轴后，才调用已配置的文字服务。平台已经生成的自动字幕也属于现成文字，不需要扩展重新识别音频。

原文语言为自动时优先英文、已知人工轨优于相同语言自动轨；显式指定原文语言时只选择匹配轨道。目标语言轨道和未标明语言的轨道不会被快速入口自动选择。需要其它语言或手动字幕时，点“选择轨道 / 导入字幕”。

没有可用字幕、平台要求登录或返回空体时显示具体原因。不会自动录音、上传音频、调用ASR、切代理、构造签名/令牌或改用别的服务。用户可以自行在原站检查访问状态或导入SRT/VTT；AI录音仍在工作台中单独启动。

## 调用链与时间轴

```text
点击VIDEO_QUICK → operation token
  → 注入顶层视频脚本/CSS → 当前视频/CID身份
  → DISCOVER（主播放器优先）→ 按原文/目标语言选择原生轨道
  → 若无匹配原生轨道：读取当前播放器的合法字幕元数据并选轨
  → READ原生文字或平台字幕文件 → 验证非空、唯一ID、真实start/end
  → 核对设置revision、视频身份、停止token
  → 创建kind=video的文字任务 → 向原documentId发INIT
  → 当前播放位置附近字幕先批量翻译 → 按ID回填TextTrack/容器双语层
```

网站元数据只查询一次即可用于紧接着的字幕下载，读前、读后及启动前仍核对当前视频/CID，不能拿缓存绕过换P检查。原生READ与INIT绑定注入时的documentId。读取期间点击停止，迟到结果不能创建文字任务；空字幕不能当成功，也不生成假时间。

视频的首个网络翻译请求可以排在尚未开始的网页请求前，仍最多两个请求在途；后续字幕批次按FIFO排队。正在远端处理的请求不抢占、不重复派发。缓存、Unicode字符预算、原时间轴、拖动、容器全屏、换源/分P取消和恢复沿用既有机制。首批完成即显示，不等待整个视频全部翻译。

## 发送哪些数据

YouTube仅请求已加载元数据提供的当前视频timedtext。B站在原站MAIN环境复用播放器已有的当前CID元数据URL，原站Cookie不转发给文字服务；字幕CDN请求credentials omit。读取后只把待译字幕文字、条目ID和语言/模型参数交给配置的文字API；视频URL、网站Cookie、音视频不进入文字请求。详细边界沿用 `data-flow.md` 与 `platform-subtitles.md`。

独立只读审查未发现新的Important/Critical问题；审查未代替浏览器测试。登录后的两站CC、真实字幕CDN差异、任意广告/直播/第三方播放器、其它浏览器、真实模型延迟和取消后的远端计费仍未验证。本版不能承诺任何视频都可获取字幕，也不能保证网络首次响应零延迟。

证据：`evidence/caption-fast-layouts.json`、`evidence/caption-fast-public-sites.json`、`evidence/page-speed-0.2.3.json`。0.2.2的基线/新版本同条件比较及已安装沉浸式翻译静态核查继续保留。
